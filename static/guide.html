How to run the Beyond Clicks study

For the person who runs the sessions. Read it once fully before the first pilot participant. Everything here works on one laptop, with no internet needed except for the AI help.

The three phases, in order: 1. Pilot study (8–12 people, no AI) → 2. Analyse the pilot and freeze the settings (you, in the dashboard, about 15 minutes) → 3. Main study (24 people). The Main study button stays locked until step 2 is done.

1. One-time setup (on the study laptop)

  1. Install Python 3.11 or newer from python.org. On the first installer screen tick "Add Python to PATH".
  2. Unzip the project folder somewhere permanent, for example Documents\Beyond-Clicks. Do not run it from inside the ZIP or from Downloads if you clean that folder.
  3. Check that the folder has a file called .env (it holds the researcher password and the AI keys). If it is missing, copy .env.example, rename the copy to .env, and ask Saumya for the values.
  4. Windows: double-click start_study.bat. Mac: double-click start_study.command (if macOS blocks it: right-click → Open).
    The first time it installs everything, which takes 3–5 minutes. Then the browser opens on the study. Keep the black window open the whole time; closing it stops the website.
  5. Open the researcher dashboard and log in with the password from .env (the line ADMIN_PASSWORD=).
  6. Settings tab:
    • Laptop name: type a name, e.g. Riya-laptop, and Save. It labels every row of the Excel sheets.
    • Consent page information: team names, contact emails, supervisor, ethics approval number (or "pending"), reward. Save. Participants see this on the consent page.
  7. Backups & tools tab → Check the AI providers → Run check. Gemini and Groq should both show "ok": true. One working is enough.
  8. Do one practice run yourself: on the start page click Start pilot study and click through to the first warm-up. Then in the dashboard Participants tab, Delete that test person so it does not count.
  9. If you tried things out a lot (several test people, a test freeze): Backups & tools → Clear all study data, type DELETE ALL. Everything recorded and the freeze are removed (a backup is saved first), the consent text and laptop name stay, and the next person is P01. Do this only before the real pilot, never during the study.

2. Before every session (2 minutes)

  1. Start the website (start_study.bat) if it is not running.
  2. Plug in the external mouse. Never use the touchpad: it changes how the mouse moves and that person's data cannot be used.
  3. Browser zoom at 100% (Ctrl+0), full screen (F11). The setup check needs a window at least 1200 px wide.
  4. Phone on silent, quiet room, no one watching the screen.
  5. Have the reward ready (the consent page says there is a bonus for each correct choice).

3. Running a pilot session (about 70 minutes)

  1. On the start page (http://localhost:8000) click Start pilot study. The site gives the person a code (P01, P02, …).
  2. Say: "Everything is explained on the screen. Choose the phone you think is best for the person on the card, as if you were really buying it. I'll be nearby if something breaks, but I can't help with the choice." Then step back.
  3. The participant goes through, on their own:
    1. consent, "About you" (age and gender, no name) and setup check
    2. 2 short warm-up tasks
    3. 4 shopping rounds with no AI, each followed by a "do you want to change your choice?" table and a confidence question
    4. a replay of each round: they watch a dot that redraws their own mouse and hold the SPACE bar whenever they remember feeling unsure
    5. 3 short interview questions
  4. You may explain the SPACE-bar replay if asked. Do not comment on phones or specs.
  5. If the browser closes by accident, open http://localhost:8000 again on the same laptop and click Continue P0x. Nothing is lost.
  6. Afterwards, in the dashboard Participants tab: the person should be completed with 4 in the Labels column. Give the reward.

4. The last 3 pilot people: switch on the AI check

The last 3 pilot participants get one extra round with the AI pop-up, to check that the AI answers make sense and arrive quickly.

  1. Before the 3rd-last pilot person (e.g. P08 if you plan 10): dashboard → Settings → Pilot AI check → tick "Give new pilot participants the extra AI round" → Save.
  2. Run those 3 sessions as normal (about 10 minutes longer).
  3. After the last one, untick it again and Save.

5. When and how to freeze

Freeze only when all of these are true

  • At least 8 pilot participants are completed (12 is better), each with 4 labels.
  • The 3 AI-check sessions are done and the AI answers looked correct.
  • You are sure no more pilot sessions will be run.
  • No simulated (test) people are in the data (Backups & tools → Delete simulated participants if unsure).

How

  1. Dashboard → Pilot analysis & freeze → leave "Include simulated participants" unticked → Run pilot analysis.
  2. The site replays every pilot round through the hesitation detector at thresholds from 1.0 to 3.0, compares the would-be pop-ups with the moments people marked as unsure, and picks the threshold with the rule we wrote down in advance: catch as many unsure moments as possible while being right at least 70% of the time with at most 1 false pop-up per round.
  3. Check the results page:
    • Threshold picked by the rule is shown. Good.
    • Phone sets: each should be about 40–60% correct. If one is far outside (e.g. 100% or 0%), stop and tell Saumya before freezing: that phone set needs fixing.
    • Leave-one-out precision should be clearly above the chance line.
  4. Take screenshots of this page (needed for the midterm slides).
  5. Click Freeze settings and open the main study and confirm.
  6. The start page now shows the Main study button unlocked. A backup is saved automatically.
What freezing means: the threshold and every detector number are locked with today's date, and every main-study participant gets exactly the same settings. You can run the pilot analysis as many times as you like before freezing. After freezing, changing anything needs "Unfreeze" with a written reason that stays in the log forever, so only do it for a serious problem and tell the team.

If no threshold passes the rule: do not freeze. Tell Saumya; the protocol allows one documented change.

6. Running a main session (about 75 minutes)

  1. Start page → Start main study. The site gives the code (M01, M02, …) and automatically picks the order of the 4 versions (No AI, Ask AI, Smart pop-up, Random pop-up). The order is random for each person but balanced overall, so you do nothing.
  2. Same short introduction as in the pilot, then step back.
  3. The participant does: consent → "About you" (age and gender) → setup check → 2 warm-ups → a practice round (shows an example pop-up and the Ask AI button) → 4 rounds, each with a short questionnaire → usability questions → ranking → 3 questions → debrief.
  4. Never tell anyone before the debrief that one round has random pop-ups. The debrief screen explains it and offers to delete their data.
  5. Goal: 24 completed participants. The design balances in groups of 4, so 24 is ideal. If someone stops early, just continue with the next person and note it.

7. After every session day

  1. Dashboard → Data & Excel → Download Excel (Pilot + Main). Save it in the team's shared folder.
  2. Dashboard → Data & Excel → Download CSV, and send that CSV file to Saumya (WhatsApp, Drive or email). It contains everything, so the full analysis can be run on another laptop.
  3. Dashboard → Backups & tools → Download full backup (.db) and put it somewhere safe (a USB drive or the team drive). This file has everything, including the raw mouse data.
  4. Close the black window to stop the website when you are done for the day.

9. Is the data safe?

SituationWhat happens to the data
Close the black window / restart the laptop / start again tomorrowKept. Everything is saved instantly to hti_study.db in the project folder and is there when you start again.
Browser closes during a sessionKept. Reopen the start page and click Continue.
Laptop crashes or a file gets damagedA complete copy is saved automatically in the backups folder: when the site starts, every 15 minutes while data changes, after every participant, at freeze, and before any delete or upload (newest 40 kept). See "Restore a backup" below.
You zip the project folder and send it to someoneThe data goes with it only if hti_study.db (and the backups folder) are inside the ZIP. Stop the website first (close the black window), then zip. The person who unzips it and starts it will see all the data in their dashboard.
You send the CSV from Download CSVThe person who uploads it sees exactly the same participants, results and analysis as you.
You send the code-only ZIP Saumya madeNo data inside: it starts empty. Use this for teammates who only need to look or test.
Someone deletes a participant by mistakeA backup was made just before the delete; restore it.

Restore a backup

  1. Close the black window (stops the website).
  2. In the project folder, rename hti_study.db to hti_study_old.db. If hti_study.db-wal and hti_study.db-shm exist, delete them.
  3. Open the backups folder, pick the backup with the right date and time, copy it into the project folder and rename the copy to hti_study.db.
  4. Start the website again. A downloaded full backup (.db) is restored the same way.

10. Golden rules

  1. One laptop for the whole study, pilot and main. The freeze uses only the pilot data on that laptop, and every participant should use the same laptop and mouse.
  2. Never delete hti_study.db or the backups folder.
  3. Never freeze with simulated (test) data, and never run the test simulator on the real study folder.
  4. Always the external mouse, zoom 100%, full screen.
  5. Do not tell participants about the random pop-ups before the debrief.
  6. On the experiment laptop: Download CSV yes, Upload CSV never.
  7. Do not share the .env file publicly: it holds the password and the AI keys.
  8. Exclude a participant (Participants → Exclude, with a reason) only for: touchpad used, did not finish the 4 rounds, a technical failure, or clearly not trying (chose within 5 seconds every round).

11. Troubleshooting

ProblemWhat to do
The page does not openThe website is not running: double-click start_study.bat and keep its window open.
The black window closes straight awayPython is missing or not on PATH: reinstall Python and tick "Add Python to PATH". Or the .env file is missing (see setup step 3).
"Main study" is greyed outThe settings are not frozen yet (section 5).
Setup check says the window is too smallPress F11 for full screen and Ctrl+0 for 100% zoom, then reload.
AI answers say "not available right now"Both AI services failed (no internet, or a key ran out). Written backup answers are shown, so the session can continue; note the participant code. Run Backups & tools → Check the AI providers and tell Saumya.
"Session not found"The browser data was cleared. Start a new session; delete or exclude the broken one.
Forgot the passwordIt is the ADMIN_PASSWORD= line in .env (open it with Notepad).
